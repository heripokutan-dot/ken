# Muse — Antigravity 直接呼び出しブリッジ設計メモ

本ドキュメントは、Meta の個人 AI エージェントである **Muse** が、GitHub Actions を介さずに **Antigravity エージェント（モデル: `gemini-4-argon`）** を直接呼び出す仕組み（ブリッジ）の設計をまとめたものである。

---

## 目的

- **GitHub Actions 実行時間（月 2,000 分上限）の節約**
  - 従来のように GitHub Actions のワークフロー（`workflow_dispatch` 等）を起動して Antigravity エージェントを実行すると、ジョブのセットアップ・ポーリング待機・後処理のたびに Actions の無料枠（月 2,000 分）を消費してしまう。
  - Muse の実行環境から GitHub Actions を使わずに Gemini API 上の Antigravity エージェントを直接呼び出すことで、Actions のランナー消費時間をゼロにし、月間上限を他の必須 CI/CD ワークフローのために温存する。
- **軽量かつ再利用可能な実行基盤の確立**
  - 既存の `notion-memory-assistant` リポジトリで実績のある `.github/scripts/run_antigravity.py` をそのまま再利用し、追加の依存ライブラリなしでシンプルに呼び出せる構成とする。

---

## 全体像

Muse がユーザーの指示を受け取り、対象リポジトリの安全なファイル群からスナップショット（コンテキスト）を構築したうえで、`run_antigravity.py` をローカルプロセスとして起動し、Gemini API（`generativelanguage.googleapis.com`）の Antigravity エージェント（`gemini-4-argon`）へ直接リクエストを送信する。

```text
[ユーザー]
   │ 指示・タスク依頼
   ▼
[Muse (Meta の個人 AI エージェント)]
   │ 1. 対象リポジトリの安全性確認（公開リポジトリ / 個人情報なし）
   │ 2. 除外ルール適用済みスナップショットの生成
   │ 3. 環境変数 GEMINI_API_KEY をセットしてスクリプト起動
   ▼
[run_antigravity.py (notion-memory-assistant より再利用)]
   │ ・Python 標準ライブラリのみで動作（urllib 等）
   │ ・エージェント指定 + モデル gemini-4-argon を指定
   ▼ (HTTPS 直接通信)
[Gemini API (generativelanguage.googleapis.com)]
   └─ Antigravity エージェント (model: gemini-4-argon)
```

### 主要コンポーネント

1. **Muse（呼び出し元エージェント）**
   - タスクの受付、対象リポジトリおよび送信対象ファイルのフィルタリング、環境変数 `GEMINI_API_KEY` の注入、`run_antigravity.py` の実行および結果の受け取りを担う。
2. **`run_antigravity.py`（ブリッジスクリプト）**
   - `notion-memory-assistant` リポジトリの `.github/scripts/run_antigravity.py` を再利用する。
   - **Python 標準ライブラリのみ**で実装されており、`pip install` 等の事前準備なしで実行可能。
   - Gemini API エンドポイント（`generativelanguage.googleapis.com`）に対して、Antigravity エージェント指定およびモデル `gemini-4-argon` を指定して通信し、完了までポーリングおよび結果取得を行う。
3. **Antigravity エージェント（`gemini-4-argon`）**
   - Gemini API 上で動作するエージェント。渡されたリポジトリスナップショットとタスク指示に基づき、コード生成・修正案・設計レビュー等の出力を返す。

---

## 処理の流れ

1. **タスク受付と対象判定**
   - Muse がユーザーからタスク指示を受け取る。
   - 対象となるワークスペース／リポジトリが「公開リポジトリ」または「個人情報を一切含まない構成」であることを確認する。個人情報を含むリポジトリ（個人の記憶・日記等）が対象の場合は処理を中断する。
2. **スナップショット（コンテキスト）の作成**
   - 対象リポジトリのファイルツリーを走査し、後述の「セキュリティと除外ルール」に従って機密ファイル・個人情報・不要なバイナリ等を除外したテキストスナップショットを生成する。
3. **環境変数の検証とスクリプト起動**
   - Muse は実行環境に `GEMINI_API_KEY` が設定されていることを確認し、サブプロセスへ環境変数 `GEMINI_API_KEY` 経由でのみ API キーを渡す（コマンドライン引数には含めない）。
   - モデルに `gemini-4-argon` を指定して `python3 run_antigravity.py` を呼び出す。
4. **Gemini API への直接接続と実行待機**
   - `run_antigravity.py` が `generativelanguage.googleapis.com` に対してエージェント指定でリクエストを送信する。
   - 非同期実行の状態をポーリングし、完了後に生成されたレスポンス（差分パッチ、ファイル内容、またはレポート）を取得する。
5. **結果の反映・報告**
   - `run_antigravity.py` の標準出力／出力ファイルから Muse が結果を受け取り、必要に応じてローカルファイルへの反映やテスト実行を行ったうえでユーザーへ報告する。

## セキュリティと除外ルール

### 1. 無料枠 Gemini API のデータ利用ポリシーへの対応

- **前提リスク**
  - 無料枠（Unpaid tier）の Gemini API を利用する場合、Google の利用規約上、送信したプロンプト・コンテキスト・出力内容が**製品改善（モデルの学習や品質評価）に使用され、人間のレビュアーが読む場合がある**。
- **基本原則**
  - **個人的な情報（PII、プライベートな日記・記憶・メモ、非公開の個人情報、認証情報）は一切送信対象に含めない。**
  - 本ブリッジの適用対象は、**公開リポジトリ（Public Repository）** または **個人情報・機密情報を一切含まないリポジトリ** に厳格に限定する。

### 2. API キーの取り扱い

- API キーは環境変数 `GEMINI_API_KEY` 経由でのみ `run_antigravity.py` に渡す。
- 以下の行為を禁止する：
  - コマンドライン引数（`--api-key` 等）での受け渡し（プロセス一覧 `ps` 等から漏洩するため）
  - ソースコードや設定ファイルへのハードコード
  - 標準出力・標準エラー出力・ログファイルへの `GEMINI_API_KEY` の出力（エラー発生時もヘッダや URL パラメータをマスクする）

### 3. スナップショットから除外すべきパスの考え方

リポジトリのスナップショットを作成して Gemini API へ送信する際は、「**外部に公開されても問題ない最小限のコード・ドキュメントのみを送る**」という考え方を採る。具体的には以下のカテゴリに該当するパスをスナップショットから必ず除外する。

1. **個人の記憶・プライベートデータ領域**
   - `memories/`、`diary/`、`notes/`、`private/` など、個人の行動記録・思考メモ・Notion 同期データ等が格納されるディレクトリやファイル。
   - たとえ同一リポジトリ内に存在していても、個人データ領域は常に除外対象とする。
2. **認証情報・シークレット・環境設定ファイル**
   - `.env`、`.env.*`、`*.pem`、`*.key`、`credentials.json`、`secrets.*`、`.netrc`、`.npmrc` 等。
   - トークンや API キー、内部エンドポイント URL が含まれ得るファイル群。
3. **Git 管理情報および CI/CD・エディタ固有設定**
   - `.git/`（過去のコミット履歴に誤って含まれたシークレットやメールアドレス等の流出を防ぐため）
   - `.github/workflows/` 等のうち、内部構成やシークレット参照を含む不要な定義ファイル
   - `.vscode/`、`.idea/` 等のローカル環境パスや個人設定が含まれるディレクトリ
4. **ビルド成果物・依存パッケージ・大容量ファイル**
   - `node_modules/`、`.venv/`、`venv/`、`__pycache__/`、`dist/`、`build/`
   - 画像・音声・動画・アーカイブ（`*.wav`、`*.mp3`、`*.mp4`、`*.png`、`*.zip` 等）やロックファイル（トークン消費の肥大化を防ぐため）

## 制限事項

- **対象リポジトリの制約**
  - 無料枠の Gemini API を前提とする限り、個人情報や非公開のプライベートデータ（`notion-memory-assistant` 内の個人メモリ本体など）を扱うタスクには本仕組みを使用できない。
- **API クォータ・レート制限（運用上限とガード方針）**
  - **運用上限**: Antigravity の上限は、エージェント呼び出しが**1日100回まで（日次でリセット）**であり、**1日のトークン総量に上限はない**。一方で、トークンは**1分あたり100K（100,000トークン）まで**という制限があり、運用上実質的に守るべきなのはこの分あたりトークン上限（TPM）である。
  - **ブリッジ側の対策（ガード方針）**:
    1. **事前見積もりと対象の絞り込み**: 実行前にスナップショットのサイズから初回送信のトークン量を見積もり、1分あたり100Kの上限に近い場合は送信対象のファイルや範囲を絞る。
    2. **消費トークンのログ記録と実行間隔の調整**: 消費トークンを実行ごとにログへ記録し、トークン消費の重い実行の直後は間隔を空けて、分あたり上限（100K/分）に重ならないようにする。
    3. **用途に応じたモデルの使い分け**: モデルは用途で使い分け、Antigravity（`gemini-4-argon`）を使う必要がない軽い作業は通常の Gemini API（`gemini-3.5-flash-lite`）に回す。
- **実行環境のタイムアウトとネットワーク依存**
  - GitHub Actions ランナーではなく Muse の実行環境から直接ポーリングを行うため、Muse 側のプロセスタイムアウトや一時的なネットワーク切断の影響を受ける。
- **標準ライブラリ構成による機能範囲**
  - `run_antigravity.py` は Python 標準ライブラリのみで動作する軽量設計であるため、高度なリトライ制御や複雑なマルチパート処理は最小限に留まる。

## 今後の課題

1. **除外フィルタの自動化と事前検査（プリフライトチェック）**
   - スナップショット生成時に `.bridgeignore`（または許可リスト方式）を自動適用し、送信前にメールアドレス・API キー形式・電話番号等のパターンが含まれていないか機械的に検査する仕組みの導入。
2. **有料枠（Paid Tier）との切り替え設計**
   - 今後、個人情報や非公開リポジトリを対象に含める必要が生じた場合に備え、データが学習・人間によるレビューに使われない有料枠（Paid API キー / Vertex AI）へ明示的に切り替える設定とガードレールの整備。
3. **エラーハンドリングと再開（レジューム）機構**
   - 長時間実行時のタイムアウトやレート制限（HTTP 429）発生時に、Muse 側でジョブ ID を保持して再ポーリングや指数バックオフを行えるようにする改善。
4. **`run_antigravity.py` の共有・同期方法の整理**
   - `notion-memory-assistant` リポジトリにある `.github/scripts/run_antigravity.py` を他リポジトリや Muse 環境から参照する際、重複コピーによるバージョン乖離を防ぐための配置・配布方法の統一。
